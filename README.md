# YouTube Whisperer — Breeze ASR 25

批次下載YouTube影片/音訊,並用本地端語音辨識模型自動產生逐字稿與SRT字幕檔。

## 設計理念

- **本地執行,不上雲端**:下載跟語音辨識全部在自己電腦跑,影音檔跟逐字稿不會經過任何第三方伺服器,免費也沒有雲端API的用量限制。
- **針對繁體中文優化**:語音辨識用的是Breeze-ASR-25(聯發科研究院針對繁體中文/中英夾雜強化過的Whisper-large-v2微調模型),比原版Whisper更適合處理中文影片。
- **GPU優先、自動降級CPU**:預設嘗試用CUDA GPU加速(`int8_float32`),偵測不到可用GPU時自動切換CPU模式(`int8`),不會直接噴錯,兩種模式共用同一個虛擬環境,不用分開安裝。
- **批次處理可中途暫停/停止**:下載跟辨識都跑在背景執行緒,暫停/停止的訊號用`threading.Event`傳遞——下載階段在「兩個網址之間」的顆粒度暫停(單一影片下載中無法安全凍結連線),語音辨識階段可以在「單一檔案轉錄中途」暫停,不用等整個檔案跑完。
- **避免重複工作**:`download_archive.txt`記錄已下載過的影片,`略過已存在的文字稿`選項避免重複跑已經轉錄過的檔案,重跑同一份清單只會處理新增的部分。
- **輸入方式彈性**:支援單一網址、播放清單網址、多網址清單(貼上或上傳.txt)、或直接上傳本機已有的影音檔(跳過下載,只做語音辨識)。
- **port不寫死**:用`socket.bind(('', 0))`動態取得空閒port啟動Streamlit,不會跟其他本機服務衝突。

## 使用說明

### 第一次啟動

1. 雙擊`01_啟動_GPU版.bat`(有NVIDIA顯卡,想用GPU加速)或`02_啟動_CPU版.bat`(沒有獨立顯卡,或就是想用CPU)。
2. 首次執行會自動跑`bootstrap.ps1`,建立虛擬環境`venv_gpu`並安裝所有套件(含PyTorch、faster-whisper、streamlit、ffmpeg執行檔),**大約下載5GB,視網速可能要10~30分鐘**,之後每次啟動就不用再等這段。
3. 第一次做語音辨識時,還會另外下載Breeze-ASR-25模型(約3GB),下載完會存在本機`models/`資料夾,之後重複使用不會再下載。
4. 啟動完成會自動開瀏覽器進入操作介面。

### 操作流程

1. **輸入來源**:選一種——單一/播放清單網址、多個網址(每行一個)、上傳.txt網址清單、或直接上傳本機影音檔(適合「已經下載好但辨識失敗」的情境,跳過下載直接辨識)。
2. **處理選項**:
   - 下載格式:僅音訊(MP3)或高畫質影片(MP4)
   - 僅下載,不進行語音辨識
   - 轉換完成後自動刪除暫存檔案
   - 略過已存在的文字稿(預設開啟,避免重複跑)
   - 同時輸出SRT字幕檔(預設開啟)
3. 按「開始」執行,過程中可以「暫停」/「繼續」/「停止」。
4. 完成後會自動打開輸出資料夾,結果存在執行當天的日期資料夾底下:`YYYYMMDD/downloads`(下載的影音檔)、`YYYYMMDD/uploads`(上傳的檔案)、`YYYYMMDD/transcripts`(純文字逐字稿),SRT字幕檔會跟影音檔放在同一個資料夾、同檔名,方便播放器自動抓字幕。

### 更新yt-dlp

雙擊`03_更新_yt-dlp.bat`可以單獨把`yt-dlp`更新到最新版,不用重新跑整個安裝流程。**這是這個工具最需要定期做的維護動作,原因見下方注意事項。**

## 注意事項

### YouTube改版可能導致下載失敗,這是外部依賴的風險,不是程式本身的bug

這個工具的下載功能完全依賴`yt-dlp`這個第三方套件去解析YouTube網頁結構、抓出實際的影音串流網址。**YouTube會不定期調整網站前端結構或防爬蟲機制**,每次調整都可能讓`yt-dlp`原本的解析邏輯失效,導致下載突然開始報錯或失敗——這不是這個專案自己的程式碼壞掉,是上游依賴的套件跟YouTube之間的攻防戰,任何用`yt-dlp`的工具都會遇到同樣的問題。

**遇到下載失敗時的處理順序**:

1. 先雙擊`03_更新_yt-dlp.bat`,更新到最新版——`yt-dlp`社群通常會在YouTube改版後的幾天到一兩週內釋出對應的修復版本,大部分下載失敗都是版本太舊造成的,更新後就能解決。
2. 如果更新到最新版還是失敗,代表YouTube這次的改版還沒有對應的修復釋出,只能**等待`yt-dlp`官方更新**,這是外部套件的釋出節奏,無法自己修——可以去[yt-dlp的GitHub](https://github.com/yt-dlp/yt-dlp/issues)看看是否已有其他人回報同樣問題、或有沒有臨時解法。
3. 這段等待期間,「上傳本機影音檔」這個輸入模式不受影響(跳過下載,只做語音辨識),如果影片已經用其他方式下載好,還是可以正常做逐字稿轉換。

### 其他注意事項

- 首次安裝需要下載約5GB的執行環境+約3GB的語音辨識模型,建議在網路穩定的環境執行,並確保硬碟至少有10GB以上可用空間。
- GPU模式需要NVIDIA顯卡且已安裝對應驅動,程式會自動偵測,偵測不到會自動改用CPU模式(速度較慢但一定能跑)。
- 下載記錄存在`download_archive.txt`,如果想重新下載某支已經下載過的影片,需要手動從這個檔案裡刪除對應紀錄。
